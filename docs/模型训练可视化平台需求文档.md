# 模型训练可视化平台需求文档

**文档版本：** v1.1  
**文档状态：** 需求已确认，可进入设计与开发  
**适用范围：** 内部演示版  

---

## 1. 项目概述

建设一个模型训练可视化平台，以流程化方式展示从数据上传、数据预处理、数据集划分、模型训练、模型评估，到模型保存、发布和对外预测服务的完整过程。

平台支持三类预测业务类型：

1. 电力负荷预测
2. 冷热负荷预测
3. 综合能耗预测

用户可以上传 CSV 数据、选择或上传 Python 脚本、执行训练并查看评估结果。训练完成的模型保存为可管理的版本，并通过 MCP 服务向外提供预测和异常切换能力。

本版本定位为**内部演示版**，重点实现完整流程和前端交互，不以生产环境的高并发、安全隔离和分布式训练为目标。

# 2. 公共业务规则

## 2.1 用户和脚本范围

本版本采用单一内部工作空间：

- 用户上传的预处理脚本和训练脚本进入全局脚本库。
- 所有平台用户可以查看并选择全局脚本。
- 暂不实现多租户隔离。
- 暂不实现细粒度角色权限。
- 只支持 Python 脚本。

脚本分为两类：

- 预处理脚本
- 模型训练脚本

每个脚本至少记录：

- 脚本名称
- 脚本类型
- 脚本版本
- 适用模型类型
- 脚本源码
- 上传时间
- 是否启用

脚本可以声明适用于一个或多个模型类型。训练页面只展示与当前模型类型兼容且处于启用状态的脚本。

## 2.2 模型类型

系统固定支持以下类型：

| 展示名称 | 系统标识 |
|---|---|
| 电力负荷预测 | `electric_load` |
| 冷热负荷预测 | `heating_cooling_load` |
| 综合能耗预测 | `integrated_energy` |

## 2.3 CSV 字段规则

训练数据字段固定为：

```text
第 1 列：时间列
第 2 列至倒数第 2 列：特征 X
最后 1 列：预测目标 y
```

预测数据不携带目标列 `y`：

```text
时间列 + 训练时使用的全部特征列
```

模型保存时必须保存完整的输入字段规范。预测时按照**字段名称**校验，不要求输入列的顺序与训练数据一致。

## 2.4 数据集划分规则

后端固定按时间顺序划分：

```text
前 80% 数据：训练集
后 20% 数据：测试集
```

要求：

- 按时间升序排序后再划分。
- 不随机打乱数据。
- 前端不展示比例编辑控件。
- 后端保存划分规则、比例和训练集/测试集的数据范围。

## 2.5 预处理规则

预处理脚本为可选项，用户可以：

- 从全局脚本库选择预处理脚本。
- 上传新的 Python 预处理脚本并保存到全局脚本库。
- 选择“不使用预处理”。

未选择预处理脚本时：

- 训练时直接使用原始特征数据。
- 测试时直接使用原始特征数据。
- 预测时直接跳过预处理步骤。
- 模型版本中记录“未使用预处理”。

选择预处理脚本时，训练、测试和预测必须使用同一套预处理逻辑。预处理器在训练阶段拟合，预测阶段只能使用已保存的拟合状态，不能重新拟合。

## 2.6 模型版本和发布规则

每次训练成功生成独立版本，不覆盖历史版本：

```text
v0-baseline
v1
v2
v3
```

每种模型类型都提供一个系统内置的 `v0-baseline`，保证首次训练或模型异常时始终存在可用备份。

新模型训练完成后进入“待发布”状态，不自动替换当前生产模型。用户确认后才发布。

新模型不要求指标一定优于当前生产模型。

## 2.7 基线模型规则

重训练时：

```text
基线模型：该类型当前有效的生产模型
候选模型：本次训练生成的新版本
```

两者必须在同一测试集上进行评估和比较。当前类型尚无用户训练版本时，使用 `v0-baseline` 作为基线模型。

## 2.8 默认模型版本规则

MCP 请求未指定模型版本时，使用该类型的：

> 当前有效、最新已发布、且未标记异常的健康版本。

以下版本不能作为默认预测版本：

- 草稿版本
- 训练中版本
- 训练失败版本
- 待发布版本
- 已标记异常版本
- 已下线版本

## 2.9 异常和回滚规则

当当前生产模型被标记异常时：

1. 记录异常原因和时间。
2. 将指定版本标记为异常。
3. 查找该类型最近的健康版本。
4. 自动切换当前有效版本。
5. 首页显示持续告警。
6. 记录回滚前后的版本。

异常告警不会因为传入 `abnormal=false` 自动解除。只有新模型成功训练并发布后，才解除该类型告警。

如果指定异常版本不是当前生产版本，只记录该版本异常，不改变当前生产版本。

# 3. 前端需求

## 3.1 前端总体要求

前端以流程化工作台为核心，使用步骤条展示训练流程：

```text
选择模型类型
→ 上传数据
→ 数据预处理
→ 数据集划分
→ 模型训练
→ 模型评估
→ 保存与发布
```

每个步骤需要有明确状态：

- 待执行
- 进行中
- 已完成
- 执行失败
- 已跳过

页面应保留用户当前任务上下文，返回上一步时不能丢失已选择的文件、脚本和配置。

## 3.2 首页

首页展示三类模型卡片，每张卡片包括：

- 模型类型。
- 当前有效版本。
- 最近训练时间。
- 当前模型状态。
- 是否存在异常告警。
- 当前使用的备份版本。
- “开始训练”按钮。
- “查看版本”按钮。

异常状态需要使用明显的告警颜色和文字，例如：

```text
该类型模型存在异常，当前已自动切换至备份版本 v1
```

首页选择模型区域必须能看到异常状态，直到新模型成功发布。

## 3.3 模型类型选择

新建训练任务时提供三个模型类型选项：

- 电力负荷预测
- 冷热负荷预测
- 综合能耗预测

选择类型后，前端加载该类型对应的：

- 当前模型信息。
- 可用预处理脚本。
- 可用训练脚本。
- 历史模型版本。
- 告警状态。

## 3.4 数据上传页面

### 3.4.1 交互要求

- 支持文件选择。
- 支持拖拽上传。
- 仅允许选择 CSV 文件。
- 展示上传中状态。
- 展示解析成功或失败状态。
- 解析失败时展示后端返回的具体原因。

### 3.4.2 数据预览

上传成功后展示：

- 全量表头。
- 每列字段角色。
- 数据总行数。
- 数据总列数。
- 前若干行样例数据。
- 时间列解析结果。
- 数值列识别结果。
- 缺失值统计。

列角色默认展示为：

```text
第 1 列：时间列
中间列：特征列
最后一列：目标列
```

本版本不提供字段角色拖拽调整功能，但前端应将识别结果展示清楚。

## 3.5 数据预处理页面

页面提供：

- 全局预处理脚本下拉框。
- 上传预处理脚本按钮。
- 脚本名称、版本和适用类型展示。
- “跳过预处理”选项。
- 预处理脚本接口规范提示。
- 执行预处理按钮。
- 执行日志区域。
- 预处理结果摘要。

如果用户选择跳过：

- 页面显示“未使用预处理”。
- 允许直接进入数据集划分步骤。
- 不发起预处理执行请求，或由后端接收空脚本标识并直接透传。

进度条采用阶段型演示：

```text
等待执行 → 数据读取 → 执行预处理 → 结果校验 → 完成
```

不显示不真实的 epoch 百分比。

## 3.6 数据集划分页面

页面展示固定划分结果，不提供比例编辑：

```text
前 80%：训练集
后 20%：测试集
```

展示内容：

- 训练集行数。
- 测试集行数。
- 训练集时间范围。
- 测试集时间范围。
- 划分方式：按时间顺序。

## 3.7 模型训练页面

页面提供：

- 全局训练脚本下拉框。
- 上传训练脚本按钮。
- 训练脚本名称和版本。
- 当前模型类型。
- 当前数据集。
- 预处理脚本或“未使用预处理”。
- 开始训练按钮。
- 训练任务状态。
- 阶段型进度条。
- 训练日志。
- 错误信息。

训练阶段展示：

```text
准备数据 → 加载训练脚本 → 执行训练 → 保存模型 → 进入评估
```

训练失败后：

- 显示失败状态。
- 显示错误日志。
- 提供重新训练入口。
- 不影响现有生产版本。

## 3.8 模型评估页面

### 3.8.1 指标展示

以指标卡片和对比表展示：

- MAE
- RMSE
- MAPE
- R²

对比表：

| 指标 | 当前生产模型 | 新训练模型 | 变化 |
|---|---:|---:|---:|
| MAE |  |  |  |
| RMSE |  |  |  |
| MAPE |  |  |  |
| R² |  |  |  |

MAPE 遇到实际值为 0 时，页面展示有效计算样本数。

### 3.8.2 图表

至少展示：

1. 测试集实际值与预测值对比折线图。
2. 预测误差折线图或误差分布图。
3. 当前生产模型与新模型的指标对比图。

图表要求：

- 横轴使用时间。
- 图例区分实际值和预测值。
- 鼠标悬停查看具体数值。
- 大数据量时允许前端抽样展示图形，但指标必须基于完整测试集计算。

## 3.9 保存与发布页面

页面展示待发布模型的：

- 模型类型。
- 新版本号。
- 训练脚本。
- 预处理脚本或跳过状态。
- 输入字段规范。
- 数据划分规则。
- 评估指标。
- 与当前生产模型的对比结果。

提供：

- 保存模型按钮。
- 发布模型按钮。
- 发布二次确认弹窗。
- 返回修改按钮。

发布成功后展示：

- 新版本已发布。
- 当前生产版本已更新。
- 原生产版本已成为可回滚版本。

## 3.10 模型版本管理页面

展示：

- 版本号。
- 创建时间。
- 训练脚本。
- 预处理脚本。
- 评估指标。
- 发布状态。
- 是否异常。
- 是否当前有效版本。
- 是否可回滚。

支持：

- 查看版本详情。
- 发布待发布版本。
- 下线版本。
- 手动回滚。
- 查看异常记录。

## 3.11 MCP 服务说明页面

前端提供 MCP 调用说明，包括：

- 服务地址。
- `predict` 工具说明。
- `mark_model_abnormal` 工具说明。
- 参数说明。
- 请求示例。
- 返回示例。
- 错误码说明。
- 当前各模型类型的默认版本。

# 4. 后端需求

## 4.1 后端总体要求

后端负责：

- 文件上传和 CSV 解析。
- 数据字段识别和校验。
- 脚本库管理。
- 预处理和训练任务执行。
- 按时间划分数据集。
- 模型评估。
- 模型版本管理。
- 发布和回滚。
- MCP 服务。
- 训练日志和异常记录。

推荐后端技术方向：

- Python
- FastAPI
- Pandas
- NumPy
- scikit-learn
- joblib
- SQLite

## 4.2 CSV 解析与字段识别

后端收到 CSV 后执行：

1. 校验文件类型和文件内容。
2. 解析表头。
3. 统计行数和列数。
4. 根据列位置识别时间列、特征列和目标列。
5. 校验时间列是否可解析。
6. 识别数值字段和缺失值。
7. 返回数据摘要和预览数据。
8. 保存数据集记录。

训练数据至少需要满足：

- 至少包含 3 列：时间列、至少 1 个特征列、目标列。
- 第一列能够解析为时间。
- 最后一列能够作为目标值使用。
- 数据行数足够完成 80%/20% 划分。

预测数据校验必须基于模型版本保存的输入规范，不能重新使用当前上传数据推断字段。

## 4.3 全局脚本库

后端提供脚本上传、列表、详情和启停管理能力。

脚本上传后：

- 保存源码。
- 生成脚本版本。
- 保存脚本类型。
- 保存适用模型类型。
- 校验 Python 文件格式。
- 加入全局脚本库。

脚本选择必须形成训练任务的固定引用。后续修改或停用脚本不能改变历史模型版本使用的脚本内容。

模型版本保存脚本源码和脚本版本快照，保证历史模型可追溯。

## 4.4 预处理任务

### 4.4.1 有预处理脚本

执行顺序：

```text
读取原始数据
→ 按时间排序
→ 划分训练集和测试集
→ 预处理器 fit(training_data)
→ transform(training_data)
→ transform(testing_data)
→ 校验处理结果
```

预处理器拟合状态需要序列化保存，并在预测时恢复使用。

### 4.4.2 跳过预处理

执行顺序：

```text
读取原始数据
→ 按时间排序
→ 划分训练集和测试集
→ 直接进入训练
```

模型版本的 `preprocess_script_id` 为空，`preprocess_used` 为 `false`。

## 4.5 数据集划分

后端统一执行：

```python
sorted_data = data.sort_values(time_column)
split_index = int(len(sorted_data) * 0.8)
train_data = sorted_data.iloc[:split_index]
test_data = sorted_data.iloc[split_index:]
```

实际实现需要额外处理：

- 时间列解析失败。
- 时间重复。
- 时间乱序。
- 数据量过少。
- 训练集或测试集为空。
- 目标值为空。

划分结果必须写入训练任务记录。

## 4.6 模型训练任务

训练任务建议采用后台任务执行，避免阻塞 HTTP 请求。

任务状态至少包括：

```text
PENDING
RUNNING
PREPROCESSING
SPLITTING
TRAINING
EVALUATING
SUCCEEDED
FAILED
CANCELLED
```

任务需要保存：

- 模型类型。
- 数据集 ID。
- 预处理脚本 ID，可为空。
- 训练脚本 ID。
- 划分比例。
- 当前阶段。
- 日志。
- 错误信息。
- 创建时间。
- 完成时间。

内部演示版可以使用模拟阶段进度，但后端必须至少能返回当前任务阶段和任务状态。

训练失败时不能改变当前生产版本。

## 4.7 模型评估

后端在测试集上计算：

- MAE
- RMSE
- MAPE
- R²

MAPE 计算规则：

- 实际值不为 0 的样本参与计算。
- 实际值为 0 的样本从 MAPE 分母中排除。
- 返回有效样本数。
- 如果没有有效样本，MAPE 返回空值并给出说明。

评估结果必须保存到候选模型版本或训练任务中。

基线评估规则：

- 优先使用该类型当前有效生产版本。
- 如果没有用户训练版本，使用该类型 `v0-baseline`。
- 基线模型与新模型使用同一测试集。
- 记录两个模型的完整指标和差值。

## 4.8 模型保存

模型版本保存以下内容：

- 模型类型。
- 版本号。
- 模型文件。
- 训练脚本源码快照。
- 预处理脚本源码快照，可为空。
- 预处理器拟合状态，可为空。
- 输入字段规范。
- 时间字段规范。
- 特征字段列表。
- 目标字段名称。
- 数据划分规则。
- 训练数据摘要。
- 测试数据摘要。
- 评估指标。
- 创建时间。
- 发布状态。
- 上一健康版本 ID。

SQLite 作为平台业务数据库，保存模型版本元数据、脚本源码、字段规范、评估指标、发布状态、告警和回滚记录。

模型文件和预处理器状态建议保存到模型文件目录，SQLite 保存路径、文件大小和校验值。内部演示版也允许在模型较小时使用 SQLite BLOB 保存。

## 4.9 模型发布

发布接口必须执行：

1. 校验模型版本状态为待发布。
2. 校验模型文件存在且可加载。
3. 校验预处理器状态与模型关联一致。
4. 将当前生产版本设置为历史版本。
5. 将当前版本记录为新模型的回滚目标。
6. 将候选版本设置为当前有效版本。
7. 更新模型类型的当前版本指针。
8. 如果存在该类型告警，解除告警。

发布失败不能改变当前生产版本。

## 4.10 异常回滚

后端维护每种模型类型的当前有效版本指针。

执行异常切换时：

1. 校验模型类型和模型版本。
2. 将模型版本标记为异常。
3. 查找最近的健康已发布版本。
4. 更新该类型当前有效版本指针。
5. 创建告警记录。
6. 创建回滚记录。

回滚目标必须满足：

- 已发布。
- 未异常。
- 模型文件可加载。
- 输入字段规范完整。

如果当前版本为 `v1`，则回滚到系统提供的 `v0-baseline`。

## 4.11 MCP 服务

### 4.11.1 `predict`

请求结构：

```json
{
  "model_type": "electric_load",
  "model_version": "v2",
  "data": [
    {
      "timestamp": "2026-01-01 10:00:00",
      "temperature": 23.5,
      "humidity": 60
    }
  ]
}
```

参数：

- `model_type`：必填。
- `model_version`：可选。
- `data`：必填，JSON 行记录数组。

省略 `model_version` 时调用当前有效最新已发布健康版本。

执行顺序：

```text
解析模型类型
→ 确定版本
→ 加载模型版本
→ 校验输入字段
→ 校验时间列和字段类型
→ 按配置执行预处理，或跳过预处理
→ 调用 model.predict
→ 返回预测值
```

成功响应：

```json
{
  "success": true,
  "model_type": "electric_load",
  "model_version": "v2",
  "preprocess_used": true,
  "predictions": [1250.36]
}
```

### 4.11.2 `mark_model_abnormal`

请求结构：

```json
{
  "model_type": "electric_load",
  "model_version": "v2",
  "abnormal": true,
  "reason": "连续预测偏差过大"
}
```

`abnormal=true` 时触发异常标记和回滚逻辑。

如果指定版本不是当前生产版本，则只标记该版本异常，不切换当前生产版本。

### 4.11.3 错误响应

统一返回结构化错误：

```json
{
  "success": false,
  "error_code": "MISSING_FEATURE",
  "message": "缺少特征字段 humidity",
  "details": {
    "missing_fields": ["humidity"],
    "required_fields": ["timestamp", "temperature", "humidity"]
  }
}
```

至少支持以下错误码：

- `MODEL_TYPE_NOT_FOUND`
- `MODEL_VERSION_NOT_FOUND`
- `MODEL_VERSION_UNAVAILABLE`
- `MISSING_TIME_FIELD`
- `MISSING_FEATURE`
- `INVALID_FIELD_TYPE`
- `INVALID_TIME_FORMAT`
- `PREPROCESS_FAILED`
- `PREDICTION_FAILED`
- `NO_HEALTHY_BACKUP`

# 5. Python 脚本接口规范

## 5.1 预处理脚本

预处理脚本建议实现：

```python
class Preprocessor:
    def fit(self, df, config):
        """使用训练数据学习参数。"""
        return self

    def transform(self, df, config):
        """使用 fit 后的参数转换数据。"""
        return df
```

接口要求：

- 输入为 `pandas.DataFrame`。
- 返回为 `pandas.DataFrame`。
- 不修改原始输入数据。
- `fit` 只能使用训练数据。
- `transform` 不能重新拟合参数。
- 输出字段必须满足训练任务的数据规范。
- 异常时抛出可读错误。

## 5.2 训练脚本

训练脚本实现：

```python
def train(X_train, y_train, X_test, y_test, config):
    """返回具有 predict(X) 方法的模型对象。"""
    model = ...
    model.fit(X_train, y_train)
    return model
```

接口要求：

- `X_train`、`X_test` 为特征数据。
- `y_train`、`y_test` 为目标数据。
- 返回对象必须实现 `predict(X)`。
- 训练失败时抛出异常。
- 脚本不能自行修改平台模型版本状态。
- 训练日志由平台统一收集。

内部演示版默认支持：

- Python
- Pandas
- NumPy
- scikit-learn
- joblib

# 8. 验收标准

## 8.1 前端验收

- 能选择三类模型类型。
- 能上传 CSV 并展示全量表头。
- 能展示第一列时间列、中间特征列和最后一列目标列。
- 能展示行数、列数、样例数据和缺失值信息。
- 能从全局下拉框选择预处理脚本。
- 能上传新的预处理脚本并在后续任务中选择。
- 能选择跳过预处理。
- 跳过后页面显示“未使用预处理”，并允许继续训练。
- 能从全局下拉框选择训练脚本。
- 能上传新的训练脚本。
- 能展示训练和预处理阶段状态、日志和演示进度。
- 能展示测试集实际值与预测值图表。
- 能展示 MAE、RMSE、MAPE、R²。
- 能展示新模型与当前生产模型的对比结果。
- 能确认发布新模型。
- 首页能展示模型异常和自动回滚信息。
- 能查看模型版本列表和版本详情。
- 能查看 MCP 调用说明。

## 8.2 后端验收

- 能解析 CSV 并按约定识别字段。
- 能按时间升序执行 80%/20% 划分。
- 能执行预处理脚本，也能在无脚本时直接跳过。
- 能保存预处理器拟合状态。
- 训练和预测使用同一套预处理逻辑。
- 能执行训练脚本并加载返回的模型。
- 能调用模型的 `predict(X)` 方法。
- 能计算四项评估指标。
- 能以当前有效版本作为重训练基线。
- 能生成独立模型版本，不覆盖历史版本。
- 能保存模型、脚本和输入字段规范的关联关系。
- 新模型未发布时不影响当前生产版本。
- 发布后正确更新当前有效版本。
- 每种类型都有 `v0-baseline`。
- 标记当前模型异常后自动回滚到最近健康版本。
- MCP 未指定版本时使用当前有效最新已发布健康版本。
- MCP 能在预测前校验字段并返回结构化错误。
- 有预处理脚本时先执行预处理，无预处理脚本时直接预测。
- MCP 能标记模型异常并触发回滚。

# 9. 本版本明确不包含的内容

以下能力暂不作为内部演示版要求：

- 生产级 Python 脚本沙箱。
- 多租户权限系统。
- 分布式训练。
- GPU 调度。
- 真实训练 epoch 级进度回传。
- 在线数据漂移监控。
- 自动超参数搜索。
- 自动判断新模型是否优于旧模型。
- 自动重新训练。
- 高并发预测服务。
- 生产级鉴权、限流和审计系统。

内部演示版仍应记录训练日志、模型版本、发布记录和异常回滚记录，避免流程不可追溯。
