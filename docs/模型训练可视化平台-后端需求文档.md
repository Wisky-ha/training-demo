# 模型训练可视化平台——后端需求文档

**文档版本：** v1.1  
**文档状态：** 需求已确认，可进入设计与开发  
**适用范围：** 内部演示版

---

## 1. 后端目标

后端负责承载模型训练全流程和模型对外服务：

- CSV 文件上传和解析
- 数据字段识别与校验
- 全局 Python 脚本库
- 可选的数据预处理
- 按时间顺序划分数据集
- 模型训练任务
- 模型评估和基线对比
- 模型保存、版本和发布
- 模型异常告警和自动回滚
- MCP 预测服务

本版本为内部演示版，不要求生产级高并发、分布式训练和脚本沙箱。

推荐技术方向：

- Python
- FastAPI
- Pandas
- NumPy
- scikit-learn
- joblib
- SQLite

---

## 2. 公共业务规则

## 2.1 模型类型

| 展示名称 | 系统标识 |
|---|---|
| 电力负荷预测 | `electric_load` |
| 冷热负荷预测 | `heating_cooling_load` |
| 综合能耗预测 | `integrated_energy` |

## 2.2 全局脚本库

用户上传的 Python 预处理脚本和训练脚本进入全局共享脚本库，所有用户可选择使用。

脚本记录：

- 名称
- 类型：`preprocessor` 或 `trainer`
- 版本
- 源码
- 适用模型类型
- 启用状态
- 上传时间

脚本被训练任务引用后，后续修改或停用不能影响已经生成的模型版本。模型版本必须保存脚本源码快照和版本信息。

## 2.3 数据字段

训练数据固定为：

```text
第 1 列：时间列
第 2 列至倒数第 2 列：特征 X
最后 1 列：目标 y
```

预测输入固定为：

```text
时间列 + 训练时的全部特征列
```

预测输入按字段名称校验，不要求列顺序一致。

## 2.4 数据划分

后端固定按时间顺序划分：

```text
前 80%：训练集
后 20%：测试集
```

先按时间升序排序，不进行随机打乱。后端保存划分比例和训练集、测试集的时间范围。

## 2.5 预处理

预处理脚本可选：

- 选择脚本时执行预处理。
- 未选择脚本时直接透传原始特征数据。
- 预测时没有预处理脚本则直接调用模型。

选择脚本时：

```text
训练：fit + transform
测试：使用训练阶段状态 transform
预测：使用已保存状态 transform
```

不能在测试或预测阶段重新拟合预处理参数。

## 2.6 模型版本、基线和默认版本

每次训练成功生成独立模型版本，不覆盖历史版本。

每种模型类型提供系统内置 `v0-baseline`，用于首次预测、首次训练对比和回滚兜底。

重训练基线优先使用该类型当前有效生产模型；如果还没有用户训练版本，则使用 `v0-baseline`。

MCP 未传入版本时，使用该类型当前有效、最新已发布、未标记异常的健康版本。

## 2.7 发布和回滚

训练成功后生成待发布版本，不自动替换当前生产模型。用户确认后发布。

模型异常时切换到最近健康的已发布版本，并创建告警和回滚记录。新模型成功发布后解除该类型告警。

如果当前版本为首个用户版本，则回滚到 `v0-baseline`。

## 3. 数据集服务

## 3.1 CSV 上传接口

建议接口：

```http
POST /api/datasets/upload
Content-Type: multipart/form-data
```

上传成功后后端执行：

1. 校验文件类型和文件内容。
2. 解析表头。
3. 统计行数和列数。
4. 根据列位置识别时间列、特征列和目标列。
5. 校验第一列是否可以解析为时间。
6. 识别数值字段和缺失值。
7. 生成数据摘要和预览数据。
8. 保存数据集记录。

训练数据至少满足：

- 至少 3 列：时间列、至少一个特征列、目标列。
- 第一列可解析为时间。
- 最后一列可作为目标值。
- 数据量足够完成 80%/20% 划分。

返回内容应包含：

- 数据集 ID
- 文件名
- 行数
- 列数
- 全量字段名
- 时间字段
- 特征字段
- 目标字段
- 字段类型
- 缺失值统计
- 样例数据

## 3.2 预测输入校验

预测时必须使用模型版本中保存的输入规范校验，不得根据当前上传数据重新推断。

至少校验：

- 模型类型
- 模型版本
- 时间字段是否存在
- 所有特征字段是否存在
- 是否存在额外不允许字段，可配置为忽略或拒绝
- 字段值类型
- 时间格式
- 空数据
- 空值

```http

POST /api/scripts/{id}/enable

```

上传要求：

- 只接受 Python 文件。
- 保存脚本源码。
- 校验脚本基本格式。
- 保存脚本类型和适用模型类型。
- 生成脚本版本。
- 新脚本进入全局脚本库。

MVP 可只做语法级校验和接口执行校验，不实现生产级安全沙箱。但需要记录脚本执行日志、异常信息和任务状态。

## 5. 预处理任务

## 5.1 使用预处理脚本

执行流程：

```text
读取原始数据
→ 按时间升序排序
→ 划分训练集和测试集
→ 创建预处理器
→ fit(training_data)
→ transform(training_data)
→ transform(testing_data)
→ 校验处理结果
```

需要保存：

- 预处理脚本源码快照
- 预处理脚本版本
- 预处理器拟合后的状态
- 预处理配置

## 5.2 跳过预处理

执行流程：

```text
读取原始数据
→ 按时间升序排序
→ 划分训练集和测试集
→ 直接进入训练
```

模型版本中的配置为：

```json
{
  "preprocess_used": false,
  "preprocess_script_id": null
}
```

预测时读取该配置，直接跳过预处理。

## 5.3 预处理结果校验

后端至少校验：

- 返回对象是否为 DataFrame。
- 训练集和测试集字段是否一致。
- 行数是否符合预期。
- 是否存在无法转换的值。
- 输出特征是否为空。
- 预处理后的特征是否能被训练脚本接收。

## 6. 数据划分服务

建议固定实现：

```python
sorted_data = data.sort_values(time_column)
split_index = int(len(sorted_data) * 0.8)
train_data = sorted_data.iloc[:split_index]
test_data = sorted_data.iloc[split_index:]
```

必须处理：

- 时间解析失败
- 时间重复
- 时间乱序
- 数据量过少
- 训练集为空
- 测试集为空
- 目标值为空

训练任务保存：

- 划分方式：`time_ordered`
- 训练比例：`0.8`
- 测试比例：`0.2`
- 训练集行数
- 测试集行数
- 训练集时间范围
- 测试集时间范围

## 7. 模型训练服务

## 7.1 创建训练任务

建议接口：

```http
POST /api/training-jobs
Content-Type: application/json
```

请求至少包含：

```json
{
  "model_type": "electric_load",
  "dataset_id": "dataset-001",
  "preprocess_script_id": "script-pre-001",
  "train_script_id": "script-train-001"
}
```

`preprocess_script_id` 可为空，表示跳过预处理。

## 7.2 任务执行顺序

```text
PENDING
→ RUNNING
→ 数据读取
→ 数据校验
→ 按时间划分
→ 可选预处理
→ TRAINING
→ 保存候选模型
→ EVALUATING
→ 生成评估结果
→ SUCCEEDED
```

任务状态至少包括：

```text
PENDING
RUNNING
PREPROCESSING
SPLITTING
TRAINING
EVALUATING
SUCCEEDED
FAILED
CANCELLED
```

建议使用后台任务执行，避免阻塞创建任务的 HTTP 请求。

## 7.3 进度和日志

后端至少返回：

- 任务状态
- 当前阶段
- 阶段开始时间
- 日志内容
- 错误信息
- 创建时间
- 完成时间

内部演示版允许通过模拟等待展示阶段进度，但不要求返回真实 epoch 级进度。

训练失败时：

- 任务标记为 `FAILED`。
- 保存错误日志。
- 不生成可发布版本。
- 不改变当前生产模型。

---

## 8. 模型评估服务

后端在完整测试集上计算：

- MAE
- RMSE
- MAPE
- R²

MAPE 规则：

- 实际值不为 0 的样本参与计算。
- 实际值为 0 的样本排除。
- 返回有效样本数。
- 没有有效样本时 MAPE 返回空值并提供说明。

评估结果至少包含：

```json
{
  "mae": 0.0,
  "rmse": 0.0,
  "mape": 0.0,
  "r2": 0.0,
  "mape_valid_count": 1000
}
```

同时保存：

- 测试集时间序列
- 实际值序列
- 候选模型预测值序列
- 基线模型预测值序列
- 误差序列
- 两个模型的指标和差值

基线模型与候选模型必须使用同一测试集。

---

## 9. 模型存储和版本服务

## 9.1 模型版本内容

每个模型版本保存：

- 模型类型
- 版本号
- 模型文件
- 训练脚本源码快照和版本
- 预处理脚本源码快照和版本，可为空
- 预处理器拟合状态，可为空
- 输入字段规范
- 时间字段规范
- 特征字段列表
- 目标字段名称
- 数据划分规则
- 训练和测试数据摘要
- 评估指标
- 创建时间
- 发布状态
- 上一健康版本 ID

## 9.2 版本状态

建议使用：

```text
DRAFT
TRAINING
READY
PUBLISHED
RETIRED
ABNORMAL
FAILED
```

版本规则：

- 训练成功后为 `READY`。
- 用户发布后为 `PUBLISHED`。
- 当前生产版本只能有一个。
- 异常版本不能作为默认预测版本。
- 历史版本不得被覆盖。

## 9.3 存储方式

SQLite 作为平台业务数据库，保存：

- 模型版本元数据
- 脚本源码
- 输入字段规范
- 评估指标
- 发布状态
- 告警和回滚记录

模型文件和预处理器状态建议保存到模型文件目录，SQLite 保存路径、大小、校验值和关联关系。内部演示版如果模型较小，也可以使用 SQLite BLOB 保存。

## 10. 模型发布和回滚

## 10.1 发布

建议接口：

```http
POST /api/models/{id}/publish
```

发布前校验：

1. 版本状态为 `READY`。
2. 模型文件存在且可以加载。
3. 预处理器状态与模型关联一致。
4. 输入字段规范完整。

发布时：

1. 当前生产版本变为历史版本。
2. 当前生产版本记录为新版本的回滚目标。
3. 新版本变为 `PUBLISHED`。
4. 更新模型类型的当前版本指针。
5. 如果该类型存在告警，则解除告警。

发布失败不能改变当前生产版本。

## 10.2 异常标记和自动回滚

建议接口：

```http
POST /api/models/abnormal
```

请求：

```json
{
  "model_type": "electric_load",
  "model_version": "v2",
  "abnormal": true,
  "reason": "连续预测偏差过大"
}
```

处理步骤：

1. 校验模型类型和版本。
2. 将指定版本标记为 `ABNORMAL`。
3. 查找最近的健康已发布版本。
4. 更新当前有效版本指针。
5. 创建告警记录。
6. 创建回滚记录。

回滚目标必须满足：

- 已发布。
- 未异常。
- 模型文件可加载。
- 输入字段规范完整。

如果指定版本不是当前生产版本，只标记异常，不改变当前生产版本。

## 11. MCP 服务

## 11.1 `predict`

输入：

```json
{
  "model_type": "electric_load",
  "model_version": "v2",
  "data": [
    {
      "timestamp": "2026-01-01 10:00:00",
      "temperature": 23.5,
      "humidity": 60
    }
  ]
}
```

参数：

- `model_type`：必填，模型类型。
- `model_version`：可选，模型版本。
- `data`：必填，JSON 行记录数组。

未提供 `model_version` 时，使用该类型当前有效最新已发布健康版本。

执行顺序：

```text
确定模型类型
→ 确定默认或指定版本
→ 校验版本可用性
→ 校验时间字段和特征字段
→ 执行预处理，或直接跳过
→ 调用模型 predict
→ 返回预测值
```

成功响应：

```json
{
  "success": true,
  "model_type": "electric_load",
  "model_version": "v2",
  "preprocess_used": true,
  "predictions": [1250.36]
}
```

如果指定版本为异常、训练中、待发布或已下线状态，应返回 `MODEL_VERSION_UNAVAILABLE`，不应静默改用其他版本；只有调用方省略版本时才使用默认版本解析规则。

## 11.2 `mark_model_abnormal`

输入：

```json
{
  "model_type": "electric_load",
  "model_version": "v2",
  "abnormal": true,
  "reason": "连续预测偏差过大"
}
```

`abnormal=true` 时触发异常标记和回滚逻辑。

异常告警不能通过传入 `abnormal=false` 自动解除。只有新模型成功发布后才解除该类型告警。

## 11.3 错误响应

统一返回结构化错误：

```json
{
  "success": false,
  "error_code": "MISSING_FEATURE",
  "message": "缺少特征字段 humidity",
  "details": {
    "missing_fields": ["humidity"],
    "required_fields": ["timestamp", "temperature", "humidity"]
  }
}
```

至少支持：

- `MODEL_TYPE_NOT_FOUND`
- `MODEL_VERSION_NOT_FOUND`
- `MODEL_VERSION_UNAVAILABLE`
- `MISSING_TIME_FIELD`
- `MISSING_FEATURE`
- `INVALID_FIELD_TYPE`
- `INVALID_TIME_FORMAT`
- `PREPROCESS_FAILED`
- `PREDICTION_FAILED`
- `NO_HEALTHY_BACKUP`

# 12. Python 脚本接口规范

## 12.1 预处理脚本

```python
class Preprocessor:
    def fit(self, df, config):
        """使用训练数据学习参数。"""
        return self

    def transform(self, df, config):
        """使用 fit 后的参数转换数据。"""
        return df
```

要求：

- 输入为 `pandas.DataFrame`。
- 返回为 `pandas.DataFrame`。
- 不修改原始输入数据。
- `fit` 只能使用训练数据。
- `transform` 不能重新拟合参数。
- 输出字段满足训练任务规范。
- 异常时抛出可读错误。

未选择预处理脚本时使用默认透传处理器，不执行用户脚本。

## 12.2 训练脚本

```python
def train(X_train, y_train, X_test, y_test, config):
    """返回具有 predict(X) 方法的模型对象。"""
    model = ...
    model.fit(X_train, y_train)
    return model
```

要求：

- `X_train`、`X_test` 为特征数据。
- `y_train`、`y_test` 为目标数据。
- 返回对象必须实现 `predict(X)`。
- 训练失败时抛出异常。
- 脚本不能自行修改平台模型版本状态。
- 训练日志由平台统一收集。

内部演示版默认支持 Python、Pandas、NumPy、scikit-learn 和 joblib。

# 14. 后端验收标准

- 能解析 CSV 并按位置识别时间列、特征列和目标列。
- 能按时间升序执行 80%/20% 划分。
- 能执行预处理脚本，也能在无脚本时直接跳过。
- 能保存预处理器拟合状态。
- 训练和预测使用同一套预处理逻辑。
- 能执行训练脚本并加载返回的模型。
- 能调用模型的 `predict(X)` 方法。
- 能计算 MAE、RMSE、MAPE、R²。
- 能以当前有效版本作为重训练基线。
- 能生成独立模型版本，不覆盖历史版本。
- 能保存模型、脚本和输入字段规范的关联关系。
- 新模型未发布时不影响当前生产版本。
- 发布后正确更新当前有效版本。
- 每种类型都有 `v0-baseline`。
- 标记当前模型异常后自动回滚到最近健康版本。
- MCP 未指定版本时使用当前有效最新已发布健康版本。
- MCP 能在预测前校验字段并返回结构化错误。
- 有预处理脚本时先执行预处理，无预处理脚本时直接预测。
- MCP 能标记模型异常并触发回滚。
